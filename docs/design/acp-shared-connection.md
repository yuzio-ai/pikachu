# ACP · 常驻连接与多会话

Zivvi 启动后预连接已启用的 Agent。同一启动配置使用一条常驻 ACP v1 连接，同时承载不同项目和 Worktree 的会话执行与历史操作。普通会话在空闲时保持打开。

## 连接生命周期

- 工作台读取配置后，在后台并行启动已启用的 Agent，启动后启用的配置也按同样流程连接。连接由应用持有，以 Agent 配置及其启动参数、环境和权限版本识别。共享进程从固定的应用目录启动。每次建立连接只做一次 `initialize`，等待握手的发送与历史操作共用这一次启动。预连接不创建会话或发送 prompt。
- 握手声明 `sessionCapabilities.close` 的 ACP v1 Agent 默认共享。缺少该能力或确认存在协议不兼容的配置走独立进程。预连接发现缺少关闭能力时，先清理用于握手的进程。会话操作已发出后发生超时或断线时，按原请求核对状态。
- 共享连接保持 `stdio` 打开，即使当前会话数为零。连接没有空闲超时或定时心跳。配置变更或停用时，旧连接停止接收新任务，当前轮结束后关闭旧会话。关闭后无法恢复的会话需要用户确认。新配置重新握手，停用后停止预连接。设置中的手动自检、模型探测和终端登录沿用独立路径。
- Agent 要求认证时，根据握手声明走 `authenticate` 或现有终端登录流程。启动和重连期间保持工作台可用，在用户需要操作时显示登录入口。意外断线后先确认旧进程清理，再限速重连。保留本地历史、草稿和待核对提交，已经发出且结果不明的 prompt 不自动重发。

## 会话执行与历史

普通会话按需创建或恢复。每个会话保留自己的 `cwd`、模型与模式、回合状态、历史回放、审批、文件和终端。沿用现有运行时 ID、本地会话 ID 和存储格式。传输层按 `sessionId` 分发会话事件，按 JSON-RPC 请求 ID 处理响应和请求级取消。`session/new` 回包前收到的事件有界暂存，确认归属后才交付。恢复 A 的历史可以与 B 的实时输出交错。

| 操作 | 调用时机与结果 |
| --- | --- |
| 新建或继续会话 | 首次执行新会话发 `session/new`，传入项目或 Worktree 的 `cwd`。已打开的会话直接沿用原 `sessionId`。已有历史但尚未打开时，按能力使用 `session/load` 回放历史，或用 `session/resume` 恢复上下文。 |
| 发送和停止当前轮 | `session/prompt` 发送消息，通过 `session/update` 接收输出。普通「停止」发 `session/cancel`，等原 `session/prompt` 响应确认终态。 |
| 导入 Agent 历史 | 打开导入面板或切换所选 Agent 时，用该 Agent 的常驻连接调用 `session/list`。按当前目录查询，使用 `nextCursor` 加载更多。重连后重新读取首页，忽略旧查询结果。关闭面板只取消该面板的请求与订阅。导入选中条目时保存本地引用，后续按需恢复。 |
| 从 Agent 历史删除 | 用户确认时固定 Agent、目录、会话段和 `sessionId`。若目标仍挂接，先完成 `session/close` 并核对清理，再在同一连接上发 `session/delete`。已释放的会话直接删除。目标变化、关闭失败或结果不明时暂停删除。成功后保留本地历史和草稿供只读查看。 |

`session/list`、`session/delete` 按握手声明的能力开放。两项历史操作可与其他会话执行并行。兼容回退的 Agent 沿用原有按需控制连接。删除 Zivvi 项目按原有本地删除语义处理。

## `session/close` 的触发条件

`session/close` 释放指定 `sessionId` 的运行时会话，成功后核对该会话的客户端终端清理。删除手动「断开连接」入口和 35 分钟空闲回收。切换查看对象、浏览本地历史、打开或关闭历史导入面板，以及一轮消息正常结束时，普通会话保持打开。

| 场景 | 行为 |
| --- | --- |
| 归档、确认切换 Agent 或删除项目 | 操作自身负责释放涉及的已打开会话。仍在运行、等待交互或有待核对提交时，先解决对应事项。关闭结果未确认时暂停操作。归档一个关闭后无法续跑的会话前，提示用户确认后续只能浏览历史。 |
| 切换 Agent 前补读历史 | 生成交接预览时，如果源会话已释放且 Agent 支持历史回放，可用 `session/load` 临时打开源会话来补齐历史。收完回放后释放临时打开的会话。源会话原本已打开时直接使用当前记录。整个过程不发送 `session/prompt`。 |
| 删除 Agent 历史 | 目标仍挂接时先关闭目标会话，再调用 `session/delete`。 |
| 正常退出 Zivvi | 先取消历史查询并关闭历史操作连接，再结束并释放仍挂接的会话。最后关闭传输并监督清理进程，包括零会话的常驻连接。 |

关闭结果不明时保留会话的待核对状态。创建结果不明且无法确定 `sessionId` 时，暂停该连接接收新会话，已有会话可继续。接力首条提交发送前，将清理凭据关联到目标会话和实际连接实例，以便重启后核对。连接已丢失或用户确认强制结束时，按连接处理清理与断线恢复。单会话内部重试和清理失败时保留待处理状态。

## 用户界面

- 智能体设置沿用「连接」区域，显示「正在启动」「已连接」「需要登录」「正在重连」或失败原因，兼容回退的原因放在连接详情。保留现有「检查连接」入口。
- 会话标签和侧栏卡片显示当前会话状态。智能体设置的连接区域显示 Agent 连接状态。实际发送需要等待时，在输入框显示连接或恢复进度，防止重复提交。失败时保留草稿并提供登录或重试。重连后仍对已发出但结果不明的消息显示「结果待核实」。移除手动断开后，同步调整依赖该操作的阻塞提示。
- 共享进程强制结束沿用现有确认面板，列出将断开的会话，并标记仍在运行或等待审批的会话。确认时重新核对连接实例和受影响名单，变化时重新提示。

## 验证与启用

真实 Agent 互通单独记录。每次报告记录实际启动入口、参数和进程报告的版本，以及接口声明、行为测试和双会话隔离结果。

- 扩展合成探针。验证同一 PID 只握手一次。并发启动只创建一个进程，两个 Worktree 的执行、历史分页和删除共用该连接，目录、审批、文件、终端和回放互不串线。停止、关闭或删除 A 时，B 仍继续运行。关闭导入面板或释放最后一个会话后仍能复用连接。普通会话长时间空闲后沿用原 `sessionId`。
- 覆盖早到或迟到的事件、关闭失败、创建结果未知、重连、接力恢复、配置变更、兼容回退和应用退出。验证现有归档、切换 Agent、删除项目和删除历史入口可自行释放目标会话。以可复核候选交独立审查，同步更新 README 和总体设计。
- 工程验收使用通用 ACP v1 夹具。真实互通和资源测量单独记录。用同一 ACP 实现与工作负载比较共享和独立进程路径，记录新会话就绪延迟，在零会话及 1、5、10 个会话完成一轮后的稳定空闲状态下测量 Zivvi 和受管进程树的内存、CPU 和进程数。分开报告常驻连接基线和新增会话成本。真实模型调用和原生验收遵循项目授权。
