# 设置分组与交互设计

工作台使用 ACP。每个智能体配置独立保存运行环境、模型偏好和客户端权限。

2026-11-25 确认的智能体页平铺布局、默认模型入口和高级设置见 [智能体设置定稿](provider-settings.md)。

## 设置入口

点击全局状态栏的齿轮或按 ⌘, 打开工作台设置面板。面板左侧依次显示「通用」「项目」「智能体」「已归档」，右侧显示所选页面，齿轮首次进入「通用」。连接错误中的「打开连接设置…」直接定位到对应智能体的「连接状态」。保留原有 modal 协调，让关闭设置后仍能处理待响应的运行时交互。

设置面板随工作台窗口宽、高变化：各轴在达到最大尺寸 `1600 × 1060` 前保持 `72 pt` 总留白（每侧约 `36 pt`），任一轴触及上限后以 `1600` 宽或 `1060` 高封顶，对应轴留白随窗口继续增大而增加（例如默认窗口 `1120 × 780` 下为 `1048 × 708`，两轴总留白均为 `72 pt`；超宽窗口 `2560 × 1440` 下封顶 `1600 × 1060`，水平与垂直分别剩余 `960 pt` 与 `380 pt`）。左侧导航栏按面板宽度的 20% 自适应（`136–216 pt`），标题、关闭按钮、栏目和智能体标签固定，超出可用空间时仅滚动正文。右侧滚动条保持贴面板右边界，正文限制最大阅读宽度 `880 pt` 并水平居中以免大窗下过度拉伸。调整窗口大小不关闭面板，也不重置所选栏目。

| 栏目 | 内容和操作 |
|---|---|
| 通用 | 「任务结束通知」开关、系统通知权限状态、界面语言、字体大小、文件打开方式、发送快捷键、Antigravity 额度和会话标题。 |
| 项目 | 用顶部选择器切换已登记的项目，包含尚无会话的项目。可改显示名称、查看工作目录、查看或刷新规则与 Skills 的来源，以及重新定位或删除项目。没有项目时显示空状态和「打开项目…」。 |
| 智能体 | 每个智能体一个标签。正文依次显示连接状态、模型和高级设置。 |
| 已归档 | 查看和打开归档会话。 |

### 共用视觉规范

适用于「通用」「项目」「智能体」「已归档」四页。 [智能体设置定稿](provider-settings.md)

- **面板与导航。** 沿用现有原生设置面板、尺寸、标题栏和滚动区域。未选中项使用次级文字和线图标，选中项使用工作台会话卡片的 `ZivviTheme.selected` 底色和主文字色。关闭按钮采用次级颜色，点击范围、焦点反馈及键盘关闭行为沿用现有实现。全局搜索待栏目增多后评估。
- **分组。** 正文直接铺在 `ZivviTheme.pageBackground` 上。分组标题、行标签和细分隔线对齐正文左边界，以标题和组间留白建立层级。输入框、按钮、选中态和状态反馈沿用各自的样式。面板保留原生外部阴影。 [设计令牌](../../DESIGN_TOKEN.md)
- **设置行。** 标签用常规字重，说明用次级文字。右侧控件沿同一边界对齐。同类菜单、文本框和按钮在当前字号档采用一致高度与圆角。较窄或文字放大时就地换行，必要时把长路径的输入框和复杂控件移到标签下方。行内的错误、保存、加载和禁用说明保持可见，键盘焦点始终可辨。
- **通用。** 「通知」放任务通知与系统权限状态。「界面与文件」放语言、字号和文件打开方式。「输入与对话」设置发送快捷键。「额度」控制全局状态栏的 Antigravity 入口。
- **项目。** 固定当前项目选择器。正文按项目资料、项目资源和项目维护分组。删除入口位于页尾，以细分隔线与项目维护区区分。 [项目设置定稿](project-settings-layout.md)
- **智能体。** 连接状态位于页首。默认模型和模型目录归入同一平铺区域。运行环境、认证、环境变量、客户端权限和管理归入默认收起的高级设置。 [智能体设置定稿](provider-settings.md)
- **已归档。** 页首按项目筛选，列表按项目标题分组。组内会话以细分隔线区分，每行提供查看会话和取消归档。

原生验收覆盖设置栏目及智能体标签内的连接和模型区域。核对默认窗、大窗、最窄支持窗、中英文、浅色／深色和大字号下的标题、分组间距、控件对齐和长路径换行。使用键盘和 VoiceOver 核对侧栏选中态、关闭按钮、主表单控件和新增删除入口。用现有模型列表、环境变量与自检失败夹具核对切页和窄窗下的列表及状态反馈。

### 项目

- 侧栏「筛选与显示」可按项目筛选或切回「全部项目」。有已启用的智能体时，菜单提供「从 Agent 导入会话」。选择项目后可按智能体支持的历史能力浏览或导入。
- 设置内按项目 ID 选择，独立于工作台筛选和会话选择。初次进入优先显示工作台所选项目，否则选列表第一项。同名项目可通过工作目录区分。
- 「项目资源」中的「刷新来源」重新检查当前目录的规则与 Skills。重新定位使用目录选择器，复用现有的运行保护、路径校验与项目标识。取消选择保留原路径。结果和错误在设置内可见，异步结果按发起时的项目归属显示。

#### 历史设计：内置 Pi 的项目信任

本节记录 2026-11-20 的旧版实现及当时的验收项。内置 Pi 退役后，该开关和启动参数已移除。

在「设置 → 项目」的工作目录下面显示「加载项目提供的 Pi 配置」开关，默认关闭。文案说明开关影响 Pi 启动时加载的项目设置和系统提示。项目主目录和同仓库的可用 Worktree 都可以在这里选择，界面显示当前设置对应的完整目录。进入项目页或换选项目时默认查看主目录。此选择只决定编辑哪个目录的开关。Worktree 列表复用现有 Git 校验。切换项目或重新定位后只应用当前项目的目录列表结果。

| 开关 | 该目录的 Pi 会话启动方式 |
| --- | --- |
| 关闭（默认） | 传入 `--no-approve`，跳过 Pi 信任规则控制的项目设置和系统提示。 |
| 开启 | 传入 `--approve`，允许加载该目录提供的 Pi 设置和系统提示。资源仍按当前启动参数装配。 |

两档都显式覆盖终端 Pi 的已保存信任和全局默认值。用户通常可以直接继续使用关闭档，依赖受信任项目配置的用户可为相应目录开启。执行模式和工具审批仍从会话读取。`AGENTS.md` 继续使用 Pi 的上下文规则，Zivvi 用显式会话目录参数指定存储位置。项目发现到的扩展、技能、模板和主题继续受 Zivvi 的启动参数控制。 [Pi 1.5.2 项目信任](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/security.md#project-trust)

**目录与保存。** 在本机工作台快照中按标准化并解析符号链接的绝对路径保存开启记录。完全匹配才读取开启记录，未记录目录使用默认关闭。新旧工作台都适用此默认值。切换 Worktree、回到原目录或重新定位后按目标路径查找，根目录和父目录的记录各自独立。使用已核验的实际工作目录查询并启动 Pi。重新定位和历史会话恢复仍走现有路径校验。

**生效与失败。** 保存成功后显示新值。启动、执行、等待回复或队列处理中的同目录会话需要先结束当前工作，再修改开关。设置保存期间，暂缓同目录的新连接和发送。已连接的空闲会话在下一次发送或激活时核对当前路径与信任状态，有差异时先清理旧连接并重新启动 Pi。保存失败时恢复已保存的值，并使用现有工作台保存错误反馈。旧进程清理未确认时保留草稿并提示原因。版本和模型探测使用各自的探测配置。

| 验收项 | 核对方法 |
| --- | --- |
| PRT-01 初始值与界面 | 在原生 macOS 隔离工作区核对已有、新建及无会话项目。确认开关默认关闭，目录可辨，键盘和辅助功能可操作，中英文显示正确。 |
| PRT-02 目录与持久化 | 使用带主目录和两个 Worktree 的临时仓库，核对分别设置、重启、往返切换、重新定位至已配置和未配置的目标目录。检查路径别名解析、失效的 Worktree 和迟到的列表结果。 |
| PRT-03 Pi 装配 | 用隔离的 Pi 1.5.2 配置逐档核对三个执行模式的实际启动参数。用本地夹具令仓库提供可观测设置，确认关闭和开启的结果，以及终端已有信任规则被显式参数覆盖。确认会话存储、所选扩展和上下文规则的实际路径。 |
| PRT-04 连接与失败 | 覆盖同目录的任务执行、等待审批、排队、空闲重连与跨目录并行。注入保存失败和进程清理失败，核对已保存值、草稿、错误提示和对后续执行的影响。 |

### 通用

- **通知**默认关闭。开启时请求 macOS 通知权限。权限被拒绝时显示状态和系统通知设置入口。每次返回 App 时更新权限状态。
- 仅在 Zivvi 位于后台时，为实时执行中已确认完成或失败的轮次发送一次通知，使用稳定轮次 ID 去重。停止、结果不确定、历史导入、前台执行及重复事件均不触发。系统横幅仅显示通用文案；点击完成、失败或工具审批通知时打开对应会话，冷启动时等待工作台读取完成。目标会话不存在时仅打开工作台，不切换会话。现有应用内错误、待审批和交互提醒照常显示。
- **文件打开方式**决定编辑区的外部打开按钮和对话文件链接回退时使用的应用：「系统默认（默认）」「Xcode」「Visual Studio Code」「自定义命令」。选择编辑器时按 `:行号` 定位；自定义命令支持 `{path}` 与 `{line}` 占位符。所选应用不可用时改用系统默认，仍无应用则改为在 Finder 中显示。设置即时生效，无需重启。
- **界面语言**提供「跟随系统（默认）」「简体中文」「English」。选择存为 Zivvi 的本机偏好，并提示「重新启动」或「稍后」。正在执行时默认「稍后」，选择重启后沿用安全退出的停止确认、草稿保存与进程清理。统一覆盖设置、主窗口、菜单、应用提供的弹窗文本及各模块本地化资源。保留对话和模型原始内容。
- **会话标题**提供「自动（默认）」「指定模型」「关闭模型生成」。模式、模型和命名规则在工作台统一保存，适用于所有项目。规则留空时使用内置规则。指定模型当前不可用时保留选择并显示回退说明。
- 自动模式按「智能体」列表顺序探测可独立生成标题的配置，使用该智能体保存的默认模型或智能体的当前默认模型。目前支持 Claude Agent ACP 0.88 起的 0.x 版本和 Claude Code 2.1.293 起的 bare 模式，需要 API Key 或受支持的云服务认证。 [Claude Code bare 模式](https://code.claude.com/docs/en/headless#start-faster-with-bare-mode)
- 新会话先显示本地标题。确认收到首条正文后，受监督的独立进程只接收完整正文和命名规则，关闭工具、扩展、MCP、上下文和会话写入。不可用、超时或输出无效时保留本地标题。纯附件、导入、恢复、交接保留原有标题，手动重命名优先。设置改变、归档或删除后忽略迟到结果。

### 智能体

- 当前智能体标签顶部显示连接状态和检查动作。配置问题可直达高级设置中的对应项。高级设置默认收起，保留运行配置、认证、环境变量、客户端权限和移除入口。
- 模型区顶部显示新会话默认模型。「更换默认模型…」也提供恢复智能体默认的入口。已有会话仍使用各自的模型、推理强度和智能体支持的模式。
- 模型列表支持在当前智能体目录中搜索，按「收藏」「其他模型」「已从选择器隐藏」分组。隐藏组默认折叠。各模型的行菜单提供收藏、选择器可见性和复制模型 ID 操作。默认模型、收藏和可见性按智能体保存在本地工作台。

#### ACP 子进程环境变量

普通变量按运行时保存在本地工作台设置中，并在下次启动对应子进程时生效。升级后从空配置开始，用户可重新录入所需变量。保存失败时，保留上次配置与编辑草稿。API Key 和登录凭据由 Agent 管理。只从环境变量读取 Key 的 Agent 由其外部启动环境提供。

#### Pi 子进程环境变量历史设计

- 设置页仅列出用户保存的变量。名称使用字母或下划线开头，可接字母、数字和下划线，且不得重复。值按字面传递，允许空值。删除一行会撤回该项覆盖，恢复对应的继承或默认行为。`PATH` 与 `PI_CODING_AGENT_DIR` 由应用管理，从 Node 目录和 Pi 配置装配，设置表阻止保存这两个名称。
- 子进程继承 Zivvi 进程环境，并按现有方式发现代理默认值。Pi 设置中的变量逐项覆盖默认环境。`HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` 的全大写与全小写形式各视为同一项，应用显式值时一并处理继承的同项别名。原有 `--proxy` 继续覆盖本次运行的 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NODE_USE_ENV_PROXY`，优先于保存值。
- 正式运行、模型探测及版本探测复用同一套环境装配。按进程创建时的配置取值，设置变更无需中断运行中的会话。

以当前代理地址为例，可通过以下环境变量传入。系统代理自动检测也可提供相应的默认值。

```text
HTTP_PROXY=http://127.0.0.1:7897
HTTPS_PROXY=http://127.0.0.1:7897
NODE_USE_ENV_PROXY=1
```

## `127.0.0.1:7897` 的来源和用途

`127.0.0.1` 指本机，`7897` 是代理监听端口。设计调查时以 `scutil --proxy` 核实本机已启用 HTTPS 代理，地址正是 `127.0.0.1:7897`。Zivvi 的自动检测会先读进程的 `HTTPS_PROXY` 或 `https_proxy`，再读取系统 HTTPS 代理。系统检测会组装成 `http://127.0.0.1:7897`。启动配置和保存的环境变量可覆盖自动检测结果。

此前的 Pi 适配器在启动 Pi 和探测模型时，将代理变量传给子进程。依赖该代理的请求需要 `7897` 上的服务可用。系统网络设置由 macOS 管理。当时的代理检测和进程装配记录位于 `PiConfiguration.swift` 与 `PiRuntime.swift`。

## 实施与验证

项目页复用 `WorkspaceController` 和现有目录选择流程。通知接入 `onTurnFinished` 传播出的实时结算结果，保留轮次 ID、状态和结束时间，并复用现有 Git 刷新路径。语言和通知偏好保存在应用级偏好中。ACP 会话、连接自检、模型探测和控制连接共用已保存的 Agent 环境配置。

| 验收项 | 核对方法 |
|---|---|
| ST-01 设置导航 | 用原生 macOS 构建核对齿轮和连接错误入口均可进入正确栏目。检查设置打开时，主窗口从最小尺寸放大、再缩回时的布局；核对正文滚动、键盘焦点、Escape 与设置关闭后的待响应交互。 |
| ST-02 项目与筛选 | 用隔离工作区核对空列表、同名项目、无会话项目、刷新项目资源来源、重新定位成功或取消、路径冲突及执行连接保护。确认筛选只改变列表范围，项目管理不会切换会话或筛选。 |
| ST-03 通知 | 用可控运行验证完成、失败、重复事件、前后台切换、停止及历史导入。用原生环境核对首次授权、拒绝和系统恢复，并检查通知内容及每轮次数。 |
| ST-04 语言 | 切换三个语言选项，检查「稍后」保留设置、「重新启动」正常重开，以及执行中默认「稍后」和停止确认。重启后检查应用语言一致、会话内容原样显示。 |
| ST-05 ACP 环境配置 | 用隔离子进程核对会话、连接自检、模型探测和控制连接实际收到的环境。覆盖继承、显式覆盖、代理优先级、空值、保存失败、重启后按运行时隔离以及移除 Agent 后删除配置。核对日志中无变量值。 |

独立审查覆盖旧入口清理、项目操作状态、通知的触发路径与去重、语言资源加载，以及 ACP 环境变量的存储与子进程装配。静态检查和测试可覆盖状态及装配逻辑。设置导航、系统通知和重启后的语言需原生证据。
