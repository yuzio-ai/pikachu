# 设置分组与交互设计

用户已确认项目管理、通知与语言、Providers 三类设置，以及将专用代理字段改为 Pi 子进程环境变量设置的方案。

## 设置入口

沿用侧栏底部的齿轮，打开现有工作台设置面板。面板左侧依次显示「通用」「项目」「Providers」，右侧显示所选页面，齿轮首次进入「通用」。连接错误中的「打开连接设置…」直接定位到「Providers → Pi」。保留原有 modal 协调，让关闭设置后仍能处理待响应的运行时交互。

设置面板随工作台窗口宽、高变化，在四周保留留白，并设最大宽高以免最大化时过度拉伸。标题、关闭按钮、栏目和 Pi 子页切换固定，超出可用空间时仅滚动正文。调整窗口大小不关闭面板，也不重置所选栏目。

| 栏目 | 内容和操作 |
|---|---|
| 通用 | 「任务结束通知」开关、系统通知权限状态、界面语言。 |
| 项目 | 列出所有登记的项目，包含尚无会话的项目。选中一项后显示项目名、可复制的工作目录、目录用途、刷新会话和重新定位。没有项目时显示空状态和「打开项目…」。 |
| Providers | 以 Pi 为首个配置项，承接 Pi 可执行文件、Node 目录、受信任的扩展和子进程环境变量。显示复用现有 Pi 认证配置及设置生效时机。 |

### 项目

- 筛选菜单只保留「全部项目」和按项目筛选。侧栏的打开项目、新建会话与底栏的全局历史刷新沿用现有入口。
- 设置内按项目 ID 选择，独立于工作台筛选和会话选择。初次进入优先显示工作台所选项目，否则选列表第一项。同名项目可通过工作目录区分。
- 刷新只作用于当前项目。重新定位使用目录选择器，复用现有的运行保护、路径校验与项目标识。取消选择保留原路径。结果和错误在设置内可见，异步结果按发起时的项目归属显示。

#### 加载项目提供的 Pi 配置

2026-11-20 确认的设计，待实施。

在「设置 → 项目」的工作目录下面显示「加载项目提供的 Pi 配置」开关，默认关闭。文案说明开关影响 Pi 启动时加载的项目设置和系统提示。项目主目录和同仓库的可用 Worktree 都可以在这里选择，界面显示当前设置对应的完整目录。进入项目页或换选项目时默认查看主目录。此选择只决定编辑哪个目录的开关。Worktree 列表复用现有 Git 校验。切换项目或重新定位后只应用当前项目的目录列表结果。

| 开关 | 该目录的 Pi 会话启动方式 |
| --- | --- |
| 关闭（默认） | 传入 `--no-approve`，跳过 Pi 信任规则控制的项目设置和系统提示。 |
| 开启 | 传入 `--approve`，允许加载该目录提供的 Pi 设置和系统提示。资源仍按当前启动参数装配。 |

两档都显式覆盖终端 Pi 的已保存信任和全局默认值。用户通常可以直接继续使用关闭档，依赖受信任项目配置的用户可为相应目录开启。执行模式和工具审批仍从会话读取。`AGENTS.md` 继续使用 Pi 的上下文规则，Pikachu 用显式会话目录参数指定存储位置。项目发现到的扩展、技能、模板和主题继续受 Pikachu 的启动参数控制。 [Pi 1.5.2 项目信任](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/security.md#project-trust)

**目录与保存。** 在本机工作台快照中按标准化并解析符号链接的绝对路径保存开启记录。完全匹配才读取开启记录，未记录目录使用默认关闭。新旧工作台都适用此默认值。切换 Worktree、回到原目录或重新定位后按目标路径查找，根目录和父目录的记录各自独立。使用已核验的实际工作目录查询并启动 Pi。重新定位和历史会话恢复仍走现有路径校验。

**生效与失败。** 保存成功后显示新值。启动、执行、等待回复或队列处理中的同目录会话需要先结束当前工作，再修改开关。设置保存期间，暂缓同目录的新连接和发送。已连接的空闲会话在下一次发送或激活时核对当前路径与信任状态，有差异时先清理旧连接并重新启动 Pi。保存失败时恢复已保存的值，并使用现有工作台保存错误反馈。旧进程清理未确认时保留草稿并提示原因。版本和模型探测使用各自的探测配置。

### 通用

- **通知**默认关闭。开启时请求 macOS 通知权限。权限被拒绝时显示状态和系统通知设置入口。每次返回 App 时更新权限状态。
- 仅在 Pikachu 位于后台时，为实时执行中已确认完成或失败的轮次发送一次通知，使用稳定轮次 ID 去重。停止、结果不确定、历史导入、前台执行及重复事件均不触发。系统横幅仅显示通用的完成或失败文案，点击后按系统默认行为前往 Pikachu。现有应用内错误、待审批和交互提醒照常显示。
- **界面语言**提供「跟随系统（默认）」「简体中文」「English」。选择存为 Pikachu 的本机偏好，并提示「重新启动」或「稍后」。正在执行时默认「稍后」，选择重启后沿用安全退出的停止确认、草稿保存与进程清理。统一覆盖设置、主窗口、菜单、应用提供的弹窗文本及各模块本地化资源。保留对话和模型原始内容。

### Providers

- 「Pi 连接」展示运行依赖、可信扩展和「环境变量」。用名称和值两列编辑传给 Pi 子进程的变量，支持添加和移除。编辑时沿用当前忙碌和命令处理保护，保存后在下次启动 Pi 子进程时生效。可信扩展继续只在自动模式加载。Pi 认证继续复用现有配置目录。
- 「Pi 模型」设置新会话使用的默认模型，可以清除并恢复跟随 Pi 设置。已有会话的模型不变，推理强度和执行模式仍按会话配置。
- Pi 模型列表支持搜索，按「收藏」「其他模型」「已从选择器隐藏」分组。每行左侧的星号控制收藏，右侧开关控制是否出现在会话模型选择器中。选择器默认只显示可用、可见的收藏，没有可用收藏时显示全部可见模型；始终保留仍可用的当前会话模型。默认模型、收藏和可见性保存在本地工作台。

#### Pi 子进程环境变量

- 设置页仅列出用户保存的变量。名称使用字母或下划线开头，可接字母、数字和下划线，且不得重复。值按字面传递，允许空值。删除一行会撤回该项覆盖，恢复对应的继承或默认行为。`PATH` 与 `PI_CODING_AGENT_DIR` 由应用管理，从 Node 目录和 Pi 配置装配，设置表阻止保存这两个名称。
- 子进程继承 Pikachu 进程环境，并按现有方式发现代理默认值。Pi 设置中的变量逐项覆盖默认环境。`HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` 的全大写与全小写形式各视为同一项，应用显式值时一并处理继承的同项别名。原有 `--proxy` 继续覆盖本次运行的 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NODE_USE_ENV_PROXY`，优先于保存值。
- 已保存的旧代理地址，在新配置尚未初始化时迁移为 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NODE_USE_ENV_PROXY=1`。保存成功后记录迁移完成，用户之后删除变量或清空列表时不会重复导入。系统检测结果作为默认值参与启动装配。
- 变量值通过 macOS 钥匙串保存，界面默认遮蔽，按需显示。Pikachu 的配置保存与诊断不输出变量值。启动时读取失败会提示并阻止新连接，保存失败时继续使用上次成功保存的配置，迁移失败时保留旧值和重试机会。
- 正式运行、模型探测及版本探测复用同一套环境装配。按进程创建时的配置取值，设置变更无需中断运行中的会话。

以当前代理地址为例，可通过以下环境变量传入。系统代理自动检测也可提供相应的默认值。

```text
HTTP_PROXY=http://127.0.0.1:7897
HTTPS_PROXY=http://127.0.0.1:7897
NODE_USE_ENV_PROXY=1
```

## `127.0.0.1:7897` 的来源和用途

`127.0.0.1` 指本机，`7897` 是代理监听端口。设计调查时以 `scutil --proxy` 核实本机已启用 HTTPS 代理，地址正是 `127.0.0.1:7897`。Pikachu 的自动检测会先读进程的 `HTTPS_PROXY` 或 `https_proxy`，再读取系统 HTTPS 代理。系统检测会组装成 `http://127.0.0.1:7897`。启动配置和保存的环境变量可覆盖自动检测结果。

Pikachu 启动 Pi 时将环境变量传给 Pi 子进程。代理值供 Pi 的模型服务请求使用，也传入模型探测进程。若 `7897` 无服务监听，依赖该代理的请求可能失败。系统网络设置由 macOS 管理。依据见 [代理检测和环境装配](../../Modules/PiRuntimeAdapter/PiConfiguration.swift)、[设置加载](../../Pikachu/App/AppSettings.swift)和 [Pi 子进程启动](../../Modules/PiRuntimeAdapter/PiRuntime.swift)。

## 实施与验证

由一个实现者处理设置面板、入口和本地化的装配。项目页复用 `WorkspaceController` 和现有目录选择流程，并检查设置面板与目录选择器的交互。通知接入 `onTurnFinished` 传播出的实时结算结果，保留轮次 ID、状态和结束时间，继续复用现有 Git 刷新路径。将语言和通知偏好放在应用级偏好中。通过 `AppSettings` 读取 Pi 环境配置，在 `PiRuntimeAdapter` 统一装配环境并兼容诊断入口。先核对工作区中的并行修改，然后同步 README、诊断说明和侧栏文档中涉及项目操作、连接设置及代理的段落。

| 验收项 | 核对方法 |
|---|---|
| ST-01 设置导航 | 用原生 macOS 构建核对齿轮和连接错误入口均可进入正确栏目。检查设置打开时，主窗口从最小尺寸放大、再缩回时的布局；核对正文滚动、键盘焦点、Escape 与设置关闭后的待响应交互。 |
| ST-02 项目与筛选 | 用隔离工作区核对空列表、同名项目、无会话项目、项目级刷新、重新定位成功或取消、路径冲突及执行连接保护。确认筛选只改变列表范围，项目管理不会切换会话或筛选。 |
| ST-03 通知 | 用可控运行验证完成、失败、重复事件、前后台切换、停止及历史导入。用原生环境核对首次授权、拒绝和系统恢复，并检查通知内容及每轮次数。 |
| ST-04 语言 | 切换三个语言选项，检查「稍后」保留设置、「重新启动」正常重开，以及执行中默认「稍后」和停止确认。重启后检查应用语言一致、会话内容原样显示。 |
| ST-05 Pi 配置 | 用隔离子进程核对正式运行与探测实际收到的环境。覆盖继承、显式覆盖、大小写冲突、空值、删除、自动检测、旧值一次迁移、启动参数、保存失败和设置变更后重连。检查变量值不会出现在工作区和日志中。核对可信扩展与编辑保护。 |

业务实现后，独立审查应覆盖旧入口清理、项目操作状态、通知的真实触发路径与去重、语言资源加载、Pi 环境变量兼容性及历史配置迁移。修复应按受影响路径局部复审。静态检查和测试可覆盖状态及装配逻辑，设置导航、系统通知和重启后的语言需原生证据。本轮仅调查现状并提供设计，尚无业务候选或原生验收证据。
