# 工作台与应用面板统一底色

**设计已定稿** · 2026-11-24

工作台、设置和应用内功能面板共用一种随明暗外观切换的底色。对话和停靠的文件区直接铺在背景上，由现有分隔线、留白和标题区分。

## 色彩与边界

| 对象 | 方案 |
| --- | --- |
| 页面底色 | SwiftUI 内容与 AppKit 窗口使用同源的[页面底色令牌](../../DESIGN_TOKEN.md#页面底色)。 |
| 工作台 | 顶栏、左侧栏、对话、文件目录和文件预览共用页面底色。去掉 r06 外框的留白、圆角、描边和阴影。文件分隔线、拖拽、目录切换和文件标签继续沿用原有布局。停靠宽度按完整详情区计算。 |
| 设置 | 通用、项目、服务商、已归档的导航、顶部和内容区共用页面底色。新增 Agent、重启确认、删除项目和移除 Agent 的二级弹窗也使用该底色。 |
| 应用内弹窗 | 工作台的项目选择、权限交互、确认、工具失败详情、完整工具输出，以及 AppKit 独立确认面板共用页面底色。模型、工作目录、用量、Git 详情等带独立内容的功能浮层使用同色。保留浮层和弹窗现有的外形、投影与遮罩。 |
| 组件与系统界面 | 输入框、消息、代码块、选中项、表单控件、状态提示和细滚动条沿用原样式。系统文件选择器、纯选项菜单、短提示和媒体预览遮罩沿用各自样式。 |

沿用侧栏色值可以维持现有选中态的底色反差。浅色代码块和深色表单的底色会更接近页面背景，原有边框和间距继续承担区分作用。

## 实施顺序

1. 建立页面底色语义，保留 `workspace`、`surface` 等既有颜色用于局部组件。复用同一颜色定义给原生窗口和 SwiftUI 内容。检查所有使用 `flatPanelContent` 和 `anchoredPopoverCard` 的入口，按用途传入页面底色。
2. 在 [WorkbenchView](../../Zivvi/Features/Workbench/WorkbenchView.swift) 移除 r06 卡片及其宽度补偿。[WorkbenchTitlebar](../../Zivvi/Features/Workbench/WorkbenchTitlebar.swift) 与 [当时的文件面板](project-file-preview.md#旧版会话文件面板) 使用相同页面色，保持停靠到浮层时的身份、分隔线和焦点逻辑。
3. 接入 [设置面板](../../Zivvi/Features/Settings/SettingsPanel.swift)、项目与服务商的二级 sheet、[原生确认面板](../../Zivvi/DesignSystem/ConfirmationPanel.swift)及 [完整工具输出](../../Zivvi/Features/Transcript/ToolCallViews.swift)。逐个核对模型、用量、工作目录、状态／额度和 Git 功能浮层的内容背景及展示背景。纯选项菜单继续使用其原有样式。

由一名实现者负责跨入口装配。开始前核对工作区并行改动，从现有源码和 [r06 历史规格](workbench-conversation-card.md) 识别待替换的卡片逻辑。候选固定后独立审查实际入口及边界，整改由实现者处理，原审查者复查受影响路径。

## 验收

下表保留旧版布局的验收口径。现行文件区的装配见[工作台 2.0](project-file-preview.md#工作台-20)。

| 条件 | 所需证据 |
| --- | --- |
| WB-BG-01 连续背景 | 固定候选的原生浅色／深色截图。对照主窗口的文件区关闭与停靠状态，检查区域底色一致、视口边缘连续。 |
| WB-BG-02 文件面板 | 原生操作记录。覆盖文件区开关、宽度临界点、拖动、目录与正文切换、窄窗浮层及关闭后的焦点恢复。 |
| WB-BG-03 组件状态 | 截图和交互记录。核对输入框、草稿、代码块、选中与焦点状态、运行提示和细滑块。 |
| WB-BG-04 设置与弹窗 | 原生浅色／深色截图及打开关闭记录。覆盖四个设置栏目、二级弹窗、AppKit 独立确认窗、工具输出和代表性功能浮层。检查底色接缝与浮层层级。 |

截图与交互以同一固定候选为准。按 [项目规范](../../AGENTS.md) 获得执行授权后，以合成数据完成原生验收。
