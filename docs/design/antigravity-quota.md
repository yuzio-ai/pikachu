# Codex 与 Antigravity 额度

方案 r03 · 纳入 2026-11-24 用户确认的 Codex 展示修订

## 布局与设置

在工作台左侧栏底部、设置和会话统计同一行的空白处显示额度。两家都开启时从左到右显示 Antigravity、Codex，升级按钮位于最右侧。

```text
  设置  统计       Antigravity Logo 42%    Codex Logo 68%   升级
                    ━━━╺──────             ━━━━━╺────
```

- 两家共用同一种布局。上方是服务 Logo 和剩余百分比，下方是对应的进度条，整块可点击。进度条显示该服务有效窗口中的**最低已知剩余比例**。正值不足 1% 时显示「<1%」。只有来源明确返回 0 时才显示「0%」。没有有效值时显示「—」和空轨道，原因可在弹窗查看。低额度警示阈值为 10%，由可访问文本同时表达。
- 点击或键盘激活后弹出对应服务的额度明细。Codex 显示现有的额度窗口。Antigravity 按 CLI 返回的模型组和窗口列出余量及重置时间。详情沿用现有样式，提供更新时间和「刷新」。未知窗口独立标记，来源返回空结果时显示「暂无额度」。
- 侧栏最窄 220 pt。保留设置、统计、额度和升级入口的命中区域。空间紧张时收窄轨道，保留 Logo、百分比和可访问的服务名。VoiceOver 朗读服务、最低已知百分比和相应额度窗口。浅深外观、中英文和最大字号沿用设计系统。
- 设置左导航新增「额度」（Quota）页，提供「在侧栏显示 Antigravity 额度」和「在侧栏显示 Codex 额度」两个独立的本机偏好。两项默认关闭，包括升级后首次运行。开启某项立即插入对应入口。关闭立即隐藏入口和弹窗、释放空间，并停止该来源的刷新。两项都关闭时，设置与升级之间保留弹性空白。

## 查询接口与数据

### Codex

Codex 复用 `CodexQuotaClient` 的账号和额度读取路径。采用该来源已有的剩余百分比、窗口和重置时间。两个来源分别维护状态，按相同的摘要规则处理多个有效窗口。

### Antigravity

调用已安装的官方 Antigravity CLI，使用一次性的只读结构化命令：

```sh
agy -p /usage --output-format json
```

Google CLI v1.1.11 引入了这条命令的非交互输出，无需启动模型回合或消耗额度。执行前验证 CLI 版本，版本过旧或无法识别时显示升级提示。通过已有的 Antigravity CLI 路径发现逻辑找到官方二进制，使用绝对路径和固定参数直接启动子进程。用户认证由 CLI 管理。Pikachu 的 ACP 会话及其 token 统计继续由各自运行时负责。设置作用于本机 CLI 默认账号，独立于当前会话及选中的 ACP Agent。

将 `command.data.groups[].buckets[]` 作为兼容性候选结构，实施前用实际输出核对结构及必填项。命令标识、结果类型或报告结构不符合预期时，按「版本不兼容」处理。只接受有限的 0–1 余量，保留明确的 0。单个异常或缺失值显示未知。使用服务提供的窗口名和重置时间，过期后撤下对应当前值，等成功刷新再更新。详情中只保留展示必要的字段。

CLI 子进程在工作台外的中立目录启动，stdin 关闭。设置执行超时和输出上限，按请求取消并回收进程。日志及错误展示使用固定错误分类。CLI 缺失、需登录、无额度、版本不支持、临时失败分别显示对应状态。重试仍走同一只读 CLI 命令。

来源：[Google CLI 发布说明](https://antigravity.google/changelog?authuser=7)、[CLI /usage 指南](https://antigravity.google/docs/cli/commands/usage/)、[CLI 非交互输出说明](https://antigravity.google/docs/cli/headless/)、[Antigravity CLI 项目中的 JSON 结构示例](https://github.com/google-antigravity/antigravity-cli/issues/1045)。

本机 CLI 为 1.5.15。本轮只读查询两次超时，第二次的诊断涉及认证，未取得可核对的额度 JSON。实施时用已登录的 CLI 核实输出结构、余量和重置时间，再按该结构完成解析。

## 生命周期与实施

1. 在 `Pikachu/Services/` 增加独立的 Antigravity 额度客户端，复用合适的进程管理基础设施。提取两家共用的进度条样式和明细样式。沿用 Codex 数据服务，移除底栏原仪表图标入口，并将相关测试改为覆盖有效窗口的最小值投影。
2. 在 `AppSettings` 持久化两项开关，通过 `WorkbenchView` 向 `SessionSidebarFooter` 装配两个来源的状态。仅在对应开关开启、侧栏可见且工作台在前台时发起查询。Antigravity 建议每 5 分钟刷新，快照有效期上限 10 分钟。Codex 沿用现有的快照有效期和刷新触发方式。服务重置早于有效期时以重置为准。每家独立合并手动及自动请求。Antigravity 的短暂失败采用退避，连续成功的手动查询至少间隔 60 秒。
3. 关闭开关、收起侧栏、工作台退出或退到后台时停止该范围的调度并取消在途查询，丢弃已失效的迟到结果。错误时撤下当前值，快照仅保留在内存。恢复时检查有效性并按各自规则刷新。发现登出、换账号或 CLI 路径变化时撤下该来源的旧结果。复用 `SettingsPanel` 及本地化目录增加设置页，使用现有品牌资产或按项目规定登记新增资产。
