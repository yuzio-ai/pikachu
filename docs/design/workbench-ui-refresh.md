# 工作台分区命名与界面优化

**设计已确认** · 2026-11-18 · 适用于 Phase 2 开始前的单任务工作台。

[已选视觉稿 v1](workbench-ui-refresh-v1.png) 使用「查看 Native A 的历史，同时 Native B 正在执行」的示例。可执行条件、模型信息和快捷键以现有工作台规则为准。

建议保留 macOS 原生双栏，把「切换会话、阅读结果、输入任务、控制执行」放在固定位置。图 1 中，重复的品牌标题、项目级按钮和分散的底部信息占用了主界面空间。优先收紧这些区域，并让当前查看的会话与实际运行的会话始终可辨。

## 图 1 分区命名

编号供讨论和交接使用。界面只显示用户操作所需的文字。分区位置以图 1 为准，图外状态用当前工作台源码补齐。

```text
01 窗口工具栏

左侧                         右侧
02 项目侧栏                  会话工作区
   项目操作区                   03 会话标题栏
   项目组 › 会话列表            04 对话区
   连接设置入口                 05 会话用量区
                                06 消息输入区
                             07 全局运行栏
```

| 编号 | 分区 | 图 1 对应内容 |
|---|---|---|
| 01 | 窗口工具栏 | macOS 窗口控制、侧栏开关、顶部 Pikachu 标题 |
| 02 | 项目侧栏 | 品牌标记、打开项目、Native A / B 项目组、项目内会话列表、连接设置。项目路径、刷新和重新定位是项目组的操作 |
| 03 | 会话标题栏 | 正在查看的会话名、历史或执行身份、模型与思考级别、模型设置、激活会话 |
| 04 | 对话区 | 用户消息、Pikachu 回复、工具事件及展开后的详情、跟随输出控制。长历史只在这里滚动 |
| 05 | 会话用量区 | 累计 Token、估算费用、展开后的输入输出及缓存明细、当前上下文占用、统计时间与刷新 |
| 06 | 消息输入区 | 编辑草稿、发送方式、待交付队列、保留的待发送内容、发送状态待核实提示、发送按钮。图中“独立草稿 A”属于正在查看的会话 |
| 07 | 全局运行栏 | 实际执行的项目与会话、连接或运行状态、返回执行会话、停止和连接恢复动作。用图 1 的“当前没有执行会话 / 未连接”定位 |

“会话工作区”指 03–06 的容器。错误提示和等待输入提示按归属贴近对应分区。例如，历史读取失败属于 04，发送结果不明属于 06，查看其他会话时收到的扩展请求要在 07 附近保留入口。

## 推荐方案

1. **收紧导航和会话标题。** 01 保留原生窗口控件与侧栏开关。03 用「项目 / 会话」显示查看对象。模型及激活操作留在同一标题区，以便核对即将执行的会话和配置。02 的顶部保留全局打开项目、新建会话，创建目标沿用当前所选项目。没有有效项目时提供“打开项目”。项目路径移入项目详情，在激活或首次发送前仍可核对。刷新、重新定位收入项目操作菜单。设置入口固定在侧栏底部，诊断和重定位仍可用。
2. **让对话成为主阅读区。** 对话正文及输入左缘对齐。宽窗用同一居中内容列控制行宽，代码、长路径和表格可在块内横向查看，保留复制或选取。工具行默认简洁，失败、中断仍可辨认，展开保留详情和原顺序。实时输出时，主动向上浏览暂停自动跟随，出现「回到最新」；返回底部或点按钮恢复跟随。历史会话可以跳到末尾，只读浏览不启动运行时。
3. **让输入位置和发送含义稳定。** 05 在 06 上方用一行展示用量摘要并保留展开入口。06 在新会话和已有会话中都固定于下方，同一区域容纳草稿、快捷键、发送方式及按需出现的队列提示。无项目时要求先打开项目；只有已知连接问题或需要补配置时才就地给原因与修复入口。有历史内容、可编辑草稿与可执行是三种独立状态。激活确认、会话独立草稿、补充当前任务 / 完成后执行、取消及队列恢复沿用现有规则。
4. **独立展示执行对象。** 07 在空闲时压为一行连接状态。有执行会话时显示项目、会话和状态；查看另一会话时保留「返回执行会话」，可停止时直接显示「停止」。等待扩展回复、正在停止、正在清理进程或执行待核实都保留明确文字和对应操作。发送仍指向输入区绑定的会话；全局停止始终指向执行会话。
5. **采用 Pikachu 自己的视觉层级。** 系统字体、原生材质与轻边框为主。闪电黄（sRGB `#F0B524`）用于品牌闪电和「发送」。选中与焦点跟随 macOS 系统强调色。运行、失败和阻塞使用状态图标与文字。缩窄窗口时先收起低频操作和次要数据，保留目标会话、发送、状态和停止的可见性。

这是一套方向。沿用现状的实现成本最低，但项目增多后重复路径与操作会挤占会话列表，向上翻看实时输出时也需要手动处理跟随。增加常驻任务栏或三栏工作区更适合同时检查多个任务，但 Phase 2 的任务树已有独立设计，提前引入面板会占用对话宽度并增加状态归属判断。本方案的主要代价是：路径、项目维护动作和用量明细需要多一次操作。工作目录在会产生执行的入口仍需容易确认。

实现原型默认沿用当前最小窗口 **860 × 620 pt**。阅读列宽度、控件间距及明暗色对比在原生候选上确认。Phase 2 的任务树、委派、取消粒度及结果回传沿用现有设计；只读改动预览按原路线独立排期。本轮纳入的是现有工作台体验。

标题栏有足够空间时保留单行「项目 / 会话」。两个名称放不下时，项目和会话各占一行，标题栏仍可打开项目详情核对完整项目名及路径。

合入会话输出方案后，连续成功完成的工具调用默认折叠为一组，展开后仍按原顺序展示各项。执行中的工具归组时，暂停跟随的视口定位到对应组。用量或输入区导致视口高度变化时，开启跟随会继续贴底。

对话区只对已完成且需要展示的文本排版 Markdown。重新打开同一段历史时仍从源文件读取，内容逐字节一致时复用已有解析结果。

## 实施顺序与文件范围

| 顺序 | 范围 | 受影响入口 |
|---|---|---|
| 1 | 导航、标题、空状态、全局运行反馈 | `Pikachu/Features/Workbench/WorkbenchView.swift`、`Pikachu/App/PikachuApp.swift`、现有连接与模型设置入口。对照窗口工具栏与菜单命令，保持键盘入口可用 |
| 2 | 对话、工具事件、滚动锚点 | `Pikachu/Features/Transcript/TranscriptView.swift`、`Pikachu/Features/Transcript/NativeTranscript.swift`。基于现有原生 transcript 增量调整滚动和行布局 |
| 3 | 用量、输入、发送与等待状态 | `Pikachu/Features/Usage/UsageView.swift`、`Pikachu/Features/Composer/ComposerView.swift`，对照 `WorkbenchView.swift` 的历史加载、发送核对和全局提示，以及 `InteractionView.swift` 的等待回复入口 |

建议一个实现者串行完成。三步共享 `WorkbenchView` 装配与会话状态，任一布局调整都需要在正常工作台入口联验。业务规则以现有 `WorkspaceController` 和 `SessionController` 为准，布局变更后复查菜单快捷键、模态路由、持久化恢复与原生 transcript 的滚动更新路径。

## 验收标准

| 验收点 | 验证方法 |
|---|---|
| AC-01 · 导航与密度 | 默认窗口和最小窗口下，用明暗模式核对无项目、长项目名、长会话名及多项目。原生截图与键盘操作记录显示项目、会话和设置入口清晰可达 |
| AC-02 · 阅读与滚动 | 用长历史和可控流式输出检验向上浏览、回到最新、工具展开、窗口缩放、复制代码。看旧内容时锚点稳定，历史失败或中断保留可读状态 |
| AC-03 · 发送与运行归属 | 在当前执行中、切到另一会话、停止清理、等待扩展回复、配置缺失和历史损坏场景核对行为。保留草稿隔离、快捷键、确认和恢复规则。验证待发送内容仍归原会话 |
| AC-04 · 用量与辅助功能 | 核对用量归属、未知和过期状态、累计量与上下文占用；用键盘及 VoiceOver 核对会话行、工具展开、发送、运行状态、返回和停止 |
| AC-05 · 性能回归 | 使用 M3 方法对比长历史首次可读、滚动、流式输入和内存。采用同一环境、样本及构建配置。原生证据绑定本轮候选 |

实施获授权后，用隔离的本地数据与 Fake Runtime 覆盖界面状态。需要真实运行时的回归复用 M3 验证入口与授权范围；额外调用模型或操作实际工作目录前重新核对授权。独立 reviewer 检查固定候选的正常入口、执行归属、失败与恢复、可访问性及性能证据。若发现回归，原作者整改，原 reviewer 对受影响路径复查。缺少原生交互或性能证据时保留对应验收缺口。

新版复跑 M3 连续滚动时，先向上滚动到出现「回到最新」，再按 ⇧⌘G 开始采样。

长历史深处对照在独立诊断包中配置 `--scroll-start-row`（从 0 开始），跟随暂停后按 ⇧⌘H 定位。再按 ⇧⌘G 采样。事件日志记录首个可见行、偏移和显示回调计数。

## 已知问题

**WBR-V03 · 长历史在接近末尾的部分区段滚动掉帧。** 2026-11-19 用户决定暂缓优化。

在 fix-04 的 5,001 行合成历史中，切换历史 40 次后，从零基第 4929 行开始连续滚动。1099 × 930 pt、2×、60 Hz 下，每轮 4 秒、1,800 pt/s，三轮合并呈现间隔 p95 为 **46.46 ms**，超过 **20 ms** 验收门槛。第 4750 行起滚的深处组 p95 为 **18.36 ms**。后续恢复优化时沿用这两组作为对照。
