# 多 Agent 编排 · 会话接力

**已确认设计 · 2026-11-24**。首版支持用户在一轮运行结束后，从同一个 Zivvi 对话换用另一个 Agent。

## 1. 能力定义

会话接力（handoff）是 **Zivvi 编排层的执行权转移**。用户决定何时换 Agent。Zivvi 保存对话顺序和交接内容，目标 Agent 在同一工作目录创建独立的运行时会话。下一条消息由目标 Agent 执行，结果追加到原对话。原 Agent 的历史、事件和运行时标识仍归原会话段。

接力与现有编排路线的关系见 [总体设计 §5.2–5.3](../../DESIGN.md)。模型切换调整当前 Agent 的配置。委派建立有返回路径的父子任务，父 Agent 可在收到结果后继续。接力在同一条对话中顺序交棒，用户仍可浏览每段的执行记录。首版交付手动接力，自动路由、故障自动换 Agent、Agent 主动发起接力和并行协作留待后续设计。

ACP v1 的 `session/new` 创建新会话，`session/load` 恢复原 Agent 持有的会话。Zivvi 用新会话加首条 prompt 实现跨 Agent 延续。目标 Agent 能看到交接内容和用户选入的摘录。模型内部上下文、未公开推理、工具进程和旧审批回执仍留在各自的执行边界内。 [ACP 会话管理](https://agentclientprotocol.com/protocol/v1/session-setup) · [ACP 消息轮次](https://agentclientprotocol.com/protocol/v1/prompt-turn)

| 方案 | 对话连续性 | 交付代价 |
|---|---|---|
| 另建 Zivvi 对话并带交接内容 | 原历史和新回复分处两个入口 | 可以大体复用当前数据结构，用户需要跨会话查阅 |
| 同一对话关联多个运行时会话，切换时保存历史 | 同一侧栏条目、草稿和消息时间线，目标 Agent 收到有限上下文 | 需要改造会话索引、历史投影和故障恢复。推荐首版采用 |
| 持续写入统一的完整对话记录 | 活动段也可由 Zivvi 独立离线浏览 | 涉及增量写入、旧数据迁移、附件、保留期限及性能，且仍需向目标 Agent 传递可接受的上下文 |

## 2. 用户流程

1. 在空闲会话打开输入区的「智能体与模型」面板。已绑定会话在当前 Agent 旁提供「切换智能体…」。选择目标 Agent 后读取其模型及推理档位。打开和切换选项只更新面板暂选。
2. 显示「交接上下文」预览。标明目标 Agent、工作目录及可用历史范围。用户可编辑最近的请求和补充说明，选择携带的会话文件改动，或选择「不携带历史」。既有输入草稿和附件留在输入区。
3. 点击「切换」。Zivvi 保存旧段并更新下一次执行目标。面板允许在提交前取消。切换完成后，输入区显示目标 Agent 和所选模型，可重新打开交接预览。此时没有 prompt 发送。
4. 用户发送首条消息后，Zivvi 为目标 Agent 启动新会话，将交接内容和用户消息合为一次实际提交。确认送达后，时间线在该用户消息前显示「来源 Agent → 目标 Agent」。交接正文默认收起，可展开查看实际发送的内容。用户消息在带 `Go ~` 的容器中显示原文。[切换与交接展示](session-switch-presentation.md) · [品牌交互语言](../../DESIGN_TOKEN.md#品牌交互语言)
5. 在首条消息发送前，或已确认发送被拒绝后，可以改选目标并复用同一份旧段快照。已尝试启动的目标实例必须先确认关闭。时间线只显示最终生效的一次接力。目标接受消息后，再次切换产生新段。A → B → A 中，最后一次使用新的 A 会话，并携带经过 B 的交接。此前 A 的运行时会话只关联此前 A 段。

未绑定的草稿沿用首次发送前选择 Agent 的入口。已绑定会话选回当前 Agent 时，只走模型保存逻辑。运行、重试、压缩、停止、队列非空、审批待处理、清理结果未知或提交待核实期间，说明当前禁用原因。归档的对话可浏览，恢复到可执行状态后再切换。复用现有面板、模型目录、键盘焦点及本地化。接力标记作为可朗读的独立行，保持既有历史滚动锚点。

## 3. 历史归属与存储

| 对象 | 所有者 | 持久化内容 |
|---|---|---|
| Zivvi 对话 | OrchestrationCore | 稳定对话 ID、项目与实际工作目录、标题、草稿和附件、活动段引用 |
| 运行时会话段 | Zivvi 索引及对应 Agent | 段 ID、顺序、Agent 配置 ID、运行时会话 ID、模型和模式、历史覆盖范围 |
| 历史快照 | WorkspacePersistence | 已取得的用户、助手、可见工具活动和轮次元数据。按段保存，保留来源 ID 与顺序 |
| 接力记录 | OrchestrationCore | 源段与目标段、快照及版本引用、用户确认的交接内容、送达状态和首条提交 ID |

`SessionReference` 记录当前 ACP 会话和已有冻结段。断开后可读本地尾部缓存，最多 60 项。正文单项最多 8,192 字节，工具参数和输出单项最多 4,096 字节。冻结段的正文按段存入应用数据目录，SwiftData 工作区索引保存引用和元数据。 [会话和缓存模型](../../Modules/OrchestrationCore/WorkspaceModels.swift) · [历史读取](../../Modules/OrchestrationCore/WorkspaceController.swift) · [工作区存储](../../Modules/WorkspacePersistence/SwiftDataWorkspaceStore.swift)

- **快照何时保存**。每次接力时保存即将退出的段。已连接时使用当前可读的对话。已断开且原 Agent 支持恢复时，预览可发起无推理的 ACP 历史读取。只能取得尾部缓存或回放不完整时，按实际内容标记覆盖范围。无可读历史时允许用户选择「不携带历史」。切换生效前须成功保存本地快照。
- **读写界限**。冻结段的可见历史按其快照读取，活动段继续通过既有 Runtime 读取或回放。段 ID 和段内稳定消息 ID 组成时间线身份。活跃段回放只更新该段。历史工具文本保留实际可读范围和截断标记。附件保留引用与可用状态，首版不复制附件二进制到快照。段内容按需加载，在较长对话中避免因流式输出重读前段。
- **旧数据**。未接力的旧记录按隐式单段读取，接力时才将该条记录转为显式分段。保留原对话 ID、项目、目录、时间顺序、草稿、归档状态、模型和原远端索引键。历史发现和 ACP 导入用段级映射识别既有会话，避免把冻结段重新导入成侧栏条目。相同运行时会话 ID 在不同 Agent 下分别匹配。
- **内置 Pi 迁移**。升级时移除当前绑定内置 Pi 的工作台会话，原始 JSONL 留在磁盘上。当前绑定 ACP 的会话仍可读取已有的冻结段，包括早期由 Pi 产生的快照。 [本地数据与恢复](../../README.md#本地数据与恢复)
- **生命周期**。归档保留段和快照。现有远端历史删除动作必须明确指向具体 Agent 会话，并保留 Zivvi 的本地只读快照。对话或项目删除遵循既有本地删除语义，移除该记录的本地快照引用并回收无引用文件。只有用户现有的明确远端删除操作才触发 Agent 删除请求。

## 4. 新 Agent 收到什么

本地逻辑从可用历史预填最近的用户请求、最近的智能体回复和整场会话中已记录的文件改动。用户可修改请求与补充说明，逐项调整默认全选的文件改动。Zivvi 不设文件数量或交接正文的固定上限。若目标运行时拒绝过长请求，保留草稿与勾选项供用户调整。交接内容以预览确认为准，本轮附件继续走原发送路径。 [切换与交接展示](session-switch-presentation.md)

交接在运行时发送路径中作为带来源标记的历史资料，并与本轮用户原文分开。Zivvi 将交接内容与用户消息组装为目标会话的首次提交，由 ACP 适配层编码文本与附件。目标 Agent 的权限、认证、执行模式及模型按目标配置重新解析，继承的工作目录需要重新验证。预览与重试均以用户确认的内容为准。 [运行时发送接口](../../Modules/AgentRuntimeCore/Runtime.swift)

## 5. 切换事务与恢复

```mermaid
flowchart LR
    A[源 Agent 空闲] --> B[预览目标与交接]
    B --> C[保存历史并确认旧实例退出]
    C --> D[持久化目标段]
    D --> E[用户发送下一条消息]
    E --> F[目标 Agent 接受首条消息]
    F --> G[沿同一时间线继续]
```

**提交切换**。沿用 `WorkspaceController` 的会话级操作互斥。进入事务后复核同一对话、源段、目标 Agent 可用性和目录。保存冻结段快照与待交接正文，确认旧实例已关闭或原本已断开，再用一次工作区元数据提交公布旧段引用、目标段、交接记录和最新草稿。按不可变文件先写、索引后提交的顺序处理跨存储边界。索引提交前落盘的无引用文件可在下次打开时按已确认的持久化索引回收。写盘、关闭或索引提交失败时，沿原对话显示错误。源段仍为当前段。若源实例已关闭，根据原 Agent 能力允许重新连接或只读查看后重试接力。

**提交首条消息**。目标段持久化后允许重新打开对话和查看交接。待接力段的启动入口统一收口到用户发送。发送时，先复核目标配置和工作目录，再创建或重连该目标段所属的新运行时。持久化本次提交 ID、目标段、用户原文及确切交接内容，然后复用已有提交与送达状态。确认已接受后标记交接已送达，同段后续消息只走正常发送。显式拒绝则保留待交接与原草稿。结果未知则沿用提交核对入口，不自动重发或换 Agent。重启后按持久化状态恢复界面，不自行开始模型调用。 [现有发送与快照入口](../../Modules/OrchestrationCore/WorkspaceController.swift)

| 故障或并发 | 预期行为 |
|---|---|
| 预览期间来了一条新消息，或用户切换了查看对象 | 用对话 ID、源段 ID、历史版本复核。预览过期时提示更新，原目标不变 |
| 同时点击两次切换、切换和发送并发 | 只有一个操作取得当前对话的互斥权。下一次操作按重新读取的目标和草稿处理 |
| 源 Agent 清理超时或状态未知 | 保留源段，通过既有受管进程恢复入口核对。确认关闭前不启动目标 |
| 历史文件丢失、缓存截断或 ACP 空回放 | 保留本地可读历史并标为部分历史。用户确认携带范围。存储错误仍阻止提交 |
| 切换后目标认证失效，或启动／配置失败 | 保留已存的目标选择、交接和草稿，允许重试、修复配置或改选。当前工作目录不静默回退 |
| 进程在快照完成、索引提交或首条送达期间退出 | 按已提交索引恢复唯一目标；已确认送达或送达未知的消息不自动重发 |
| 旧 Agent 有迟到输出或审批 | 事件必须匹配对话、段、运行实例及请求 ID，过期事件不会写入新段或弹出审批 |

同一实例的确定送达回执可更新暂时未知的首条提交。用户核对为未送达后可恢复草稿。目标 ACP 会话无法恢复时，先确认旧实例已清理，再允许该 Agent 创建新会话重试。

ACP 目标首条提交会一并保存启动实例的清理标识。Zivvi 异常退出后，使用与该标识匹配的 Agent 和客户端终端监督记录核对清理。回执尚未确认时保留历史与草稿，并禁止执行或改选该目标。监督记录变为已确认后，可在工作台重新读取或重新打开会话，再按正常入口操作。旧索引若保留了明确拒绝目标的绑定但缺少清理标识，继续保留该对话供查看。

## 6. 实施顺序与审查

| 顺序 | 改动范围 | 完成条件 |
|---|---|---|
| 1 | `OrchestrationCore` 会话身份、段级历史定位和接力状态。`WorkspacePersistence` 按段持久化 | ACP 会话可恢复，多段记录可往返保存。旧冻结段可读，历史导入按段识别已有会话 |
| 2 | `WorkspaceController` 的接力事务，接入 `SessionController` 的空闲判断、断开、发送与恢复 | Fake Runtime 覆盖成功、失败、重启和并发，接力无立即推理，未知送达无重发，旧实例事件隔离 |
| 3 | ACP 首条提交装配，复用附件和授权路径 | 合成夹具捕获新会话收到的完整请求，核对目标配置、目录、交接范围和后续消息 |
| 4 | `ModelConfigurationPanel`、`ComposerView`、Workbench 装配、时间线投影和本地化 | 正常输入入口完成预览、切换、恢复和再次接力。侧栏归属、焦点、读取位置及现有模型切换通过回归 |

文档随实施同步 [模型选择器设计](session-model-picker.md)、[时间线设计](session-run-timeline.md) 和 [总体设计的架构与历史部分](../../DESIGN.md)。核对项目删除、历史导入、应用重启、冷启动恢复、快捷键入口和设置默认值的相关调用方。

建议单实现者负责跨层契约与固定候选，独立 reviewer 核对旧数据迁移、写入顺序、生产发送入口及迟到事件。涉及数据丢失、错误 Agent 执行、重复发送、权限继承或无法恢复的发现阻止验收。作者整改后由原 reviewer 复查现场及相邻失败路径。

## 7. 验收标准

| 验收项 | 场景与通过条件 | 证据 |
|---|---|---|
| AH-01 · 对话连续 | 用两个 ACP Agent 执行 A → B → A，侧栏 ID、草稿和目录保持一致。时间线顺序和来源正确。同一 Agent 内换模型沿用原段 | 正常工作台装配的回归与原生操作 |
| AH-02 · 历史持久 | 在线 ACP、ACP 回放、仅本地缓存和旧 Pi 冻结段均显示实际保留范围。重启后可读已保存的段，导入按段识别已有会话 | 工作区读写、索引迁移及历史投影测试 |
| AH-03 · 交接范围 | 预览与发送的交接文本一致。取消或切换本身发出零次 prompt。首条提交只一次，后续不重复注入。选「不携带历史」时仅发送用户原文及本轮附件 | Fake Runtime 或合成 ACP 记录实际请求 |
| AH-04 · 并发与退出 | 源队列、审批、关闭未知、迟到输出及同对话重复操作受控。其他独立对话的运行不受影响 | 可控时钟、进程与事件夹具 |
| AH-05 · 故障恢复 | 快照、索引和首条提交各边界注入失败及重启。保留草稿和已确认历史。源关闭未知时不启动目标，送达未知时不自动重发 | 持久化故障注入及应用装配测试 |
| AH-06 · 工作区和权限 | 目标使用原目录及目标权限。目录、认证或目标模型不可用时给出可恢复状态。预览可核对将传给新 Agent 的内容 | 适配层集成测试和两种 Runtime 的受控验证 |
| AH-07 · 可用性与长历史 | 最小窗口、明暗外观、键盘、VoiceOver 可完成流程。用千条和万条历史夹具测量接力保存耗时、正文存储大小和首次可见时间。浏览旧段时滚动锚点稳定，流式更新期间旧段读取次数为零 | 隔离原生候选、固定数据规模及运行记录 |

工程验证按仓库规范执行共享 scheme 构建、单元测试和隔离集成测试，优先使用合成数据。原生 macOS 验收需本任务明确授权，真实模型调用另核对测试账号、成本与授权。待验证项包括不同 ACP Agent 的历史与文件改动记录覆盖程度、长历史快照和分段加载的性能。
