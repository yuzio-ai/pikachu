# 首轮基线与 Phase 1 性能目标

## 已测范围

参考环境：Apple M4 Pro（Mac16,8 / arm64）、12 个逻辑处理器、24 GiB 内存、macOS 27.2.1（26B131），Xcode 27.2 / Swift 6.4.2，SwiftPM debug。后续原生 trace 沿用同机并记录显示条件；不得把本机结果推广到所有 macOS 设备。

使用同一协调器注入 100 / 5,000 条约 900 字符的最终消息，每种规模创建三个新实例。随后在 100 个事件循环轮次中追加流式文本、编辑草稿并 yield。无文件读取、历史恢复、Pi、模型网络或 SwiftUI 渲染。

```sh
.build/debug/m1-verify --baseline
```

| 指标 | 修正前 | 最终构建 |
|---|---|---|
| 100 条消息投影 | 2.10–3.78 ms | 0.43–0.61 ms |
| 5,000 条消息投影 | 2,573–2,589 ms | 13.93–19.04 ms |
| 5,000 条规模下单轮流式 / 草稿状态更新 p95 | 0.81–0.83 ms | 0.009–0.015 ms |

原始数据：[修正前](evidence/baseline/projection-before.json)、[最终构建](evidence/baseline/projection.json)。增加 ID 索引消除了随消息数增长的重复遍历。一次投影的总时间、Task.yield 时间都不能冒充用户按键到像素显示的延迟。

## 冻结目标

以下是 M3 的验收目标，不是已测结果。现在冻结，后续调整必须记录原因与旧目标，不能因验收失败静默放宽。

| 指标 | 条件与目标 |
|---|---|
| 冷进程启动 | 同机 release 构建，退出后重新启动 10 次；启动到首个可编辑窗口 p95 ≤ 1 s；Pi 连接时间单独报告，文件缓存状态明确记录 |
| 历史切换 | M0 100 / 5,000 条混合样本；选择到首屏可读 p95 ≤ 200 ms，全量加载 ≤ 1 s；执行进程切换另计 |
| 长历史滚动 | 同样本、固定窗口尺寸与显示刷新条件；帧时间 p95 ≤ 20 ms，无 > 100 ms 主线程停顿 |
| 输入响应 | 流式文本与 10 MiB 工具输出样本期间；按键到可见文本 p95 ≤ 50 ms，最大 ≤ 100 ms |
| 大输出 | 输出保留 / 截断规则固定；无协议积压持续增长；处理后常驻内存相对空闲基线增加 ≤ 200 MiB，仍满足输入目标 |
| 领域投影回归 | 本页 debug 夹具；5,000 条投影每轮 ≤ 100 ms，增量 / 草稿轮次 p95 ≤ 5 ms |

冷启动、历史切换、滚动、真实输入和大输出内存**尚无量化原生基线**。M1 已完成可重跑的领域基线与目标冻结；原生实测和目标验收保留在 M3。M2 只引入已规划的历史与持久化能力，不因基线夹具提前实现。

M3 使用固定设备、构建指纹、窗口与显示条件，按 DESIGN 的样本记录原生 trace。按 xctrace 的 toc → track → detail 流程区分主线程、SwiftUI 更新和实际帧；使用事件 / 显示时间戳定义输入端点，不把自动化工具的调用耗时当作产品延迟。连接与模型请求等待单独报告。
