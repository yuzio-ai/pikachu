## 1. 根因与实现

Pi 的 Bash 工具在 macOS 上以 detached 模式创建独立进程组。终止 Pi 的 PID 或其进程组不能覆盖这些工具；让同一 RPC 宿主定时清理也不能覆盖宿主自身被 SIGKILL 的情况。

因此新增独立可执行文件 `m0-supervisor`。RPC 宿主通过它启动 Pi，原始 JSONL stdin/stdout 保持透传；控制状态写入单独的 0700 临时目录，不混入协议流。

| 职责 | 具体行为 |
|---|---|
| 进程所有权 | 为每次运行注入独立随机环境标记；登记同用户活跃进程；结合标记和已观测父子谱系记录 PID 与启动秒/微秒 |
| 防止误杀 | 发信号前重新核对 PID 与启动时间；不按名称、工作目录或夹具 PID 判断所有权；不向不匹配的 PID 发送信号 |
| 独立监督 | 监督进程每 50 ms 检查运行时和宿主身份；宿主退出或 Pi 退出都启动清理；嵌套 setsid 不依赖原父进程仍存活 |
| 终止升级 | 先 SIGTERM，300 ms 后仍存活则 SIGKILL；在总计 3 秒的清理期限内继续发现所属后代，连续空闲 200 ms 后核验终态 |
| 槽位释放 | 只有监督进程完成且状态为 clean 才允许 close 成功；状态缺失、权限/枚举失败、监督崩溃或清理未完成均保持 unknown，拒绝新命令和槽位释放 |
| 监督信号 | 监督进程接收到 SIGTERM、SIGINT 或 SIGHUP 时走相同清理流程，而非立即退出留下工具 |
| 隐私 | 进程参数/环境只在底层短暂读取以匹配标记，不输出到日志或 IPC；临时缓冲用后清零，只输出本实例的计数与状态 |

正常发送、停止和会话语义保持不变。Agent 停止仍先 clear_queue 再 abort；监督负责进程生命周期，不替代 Agent Loop 或工具审批。

全量回归还发现并修正了退出竞态：全局 PID 枚举与身份查询不是原子操作。正常退出/回收可能使登记 PID 暂时不在快照中。实现会重新读取身份，并将仍无法确认的登记身份保留在待清理集合中；不会因一次缺失直接报失败，也不会把未确认的活跃进程判为已清理。僵尸进程只按无执行能力处理，身份不匹配时不发信号。

## 2. 新增验收

在原 30 个 M0 案例之外，增加 10 个进程监督专项：

- 双层脱离进程组且忽略 SIGTERM 的后代，运行时崩溃后三轮清理。
- RPC 宿主被 SIGKILL，运行时故意忽略 stdin EOF，由独立监督检测宿主丢失并清理，三轮验证。
- 同时运行两个受管实例并保留无关 sleep 进程；清理 A 后 B 和无关进程继续运行。
- 注入枚举失败，启动必须被拒绝，不允许任务开始。
- 强制杀死监督进程，宿主必须拒绝新命令和释放槽位；负向测试结束后使用测试救援清理。
- 向监督进程发送 SIGTERM，确认按清理流程退出，含忽略 SIGTERM 的后代。

额外自动化测试构造相同 PID、不同启动时间的身份，确认不会向实际存活的无关身份发信号。累计自动化测试为 9 项。

夹具仍记录 PID 和心跳，但仅供独立断言及测试失败救援。六个原阻塞案例的成功条件要求 `fixtureFallbackUsed == false` 和监督状态 clean，不能把救援清理当作策略成功。

## 3. 适用边界

- 本轮证明的是同用户、可检查进程环境下，Pi 1.5.2 的默认工具，以及继承执行标记或已被谱系登记的后代。环境标记是所有权辅助信息，不是安全凭据。
- 不提供操作系统沙箱。不保证进程在被观测前主动清除标记并脱离所有谱系、跨用户提权，或整个宿主与监督进程同时被强制杀死时的自动清理。需要更强边界时必须另行验证系统隔离方案。
- 监督进程单独失效时已验证会拒绝继续执行；不能将这个负向场景描述为自动清理成功。
- 本轮未验证 App Sandbox、签名后的 GUI 宿主或系统 Force Quit 对整个 App 的行为。M1 集成时须保留相同监督约束并做原生验收。
- clean 表示本策略受管边界的清理确认；无法核验已登记进程身份或取得监督终态时，不能显示“全部停止”。
