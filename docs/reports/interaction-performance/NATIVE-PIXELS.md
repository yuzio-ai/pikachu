## 测量端点

诊断应用用 ScreenCaptureKit 的 `SCShareableContent.currentProcess` 枚举本进程可捕获内容，同时核对 PID 与窗口 ID。`SCStreamFrameInfo.displayTime` 是 WindowServer 呈现时间，按主机时钟转换后与 `NSEvent.timestamp` 对齐。原始帧只在内存中计算编辑器字形统计和聊天区像素指纹。归档元数据和帧统计，测量边界止于窗口合成器，未测显示面板的实际发光。系统未授予录屏权限，窗口捕获仍成功。 [Apple SDK 的 displayTime 文档](https://developer.apple.com/documentation/screencapturekit/scstreamframeinfo/displaytime)

- 输入从 AppKit 按键事件时间计至第一次呈现相应字形。以暗色模式下依次键入的 `m` 校验字形右边界和中性笔画像素，检查每个按键都有独立匹配。执行后核对编辑器完整内容、完成状态和固定结果。报告全部按键，以及最终结果可见前的子集。
- 滚动由诊断快捷键触发，连续 4 秒，以 1,800 pt/s 移动原生聊天区。以相邻聊天区像素变化的呈现时间差计算帧间隔。期间重复画面的间隔计入下一次变化。Hangs trace 以同 PID 的起止标记核对窗口。真实滚轮另外保留，因为离散输入间的空档无法判断为持续动画漏帧。
- 冷启动从进程出生计到采样首个含编辑器占位字形的帧。捕获建立需要时间，因此这是首次可见的保守上界。启动样本使用热文件缓存，Pi 未激活。
- 历史切换从侧栏动作计至确认可读的稳定聊天区指纹。稳定画面给出首屏可读的保守上界。另记录完整模型投影绘制点，确认加载完成和投影行数。
- p95 采用 nearest-rank。滚动结果按每轮和全部区间报告。试验失败与替代候选各自保留。

录入过程现在只更新编辑器草稿和侧栏草稿标记。完整索引在合并保存或控制事件时更新。重复工具快照保持此前显示内容，避免再次布局。新增测试覆盖编辑后立即切换会话仍能保存草稿。

最终源代码通过 47 项核心测试、9 项 M1 本地回归、11 项 M2 真实回归及 8 项 M3 集成。正式包通过 deep / strict 签名检查，诊断包与正式包的主程序 Mach-O UUID 一致，只有诊断包加载测量配置。原始时间序列、逐键匹配、帧间隔、Hangs 和源代码指纹见 [证据清单](evidence/native-pixels/manifest.json)。

## 重跑方法

用 `m3-verify --prepare-native <空临时目录>` 生成工作台和负载夹具。为 `M3LoadDiagnostics.json` 设置绝对路径 `--metrics` 和 `--pixel-metrics`，并将 JSON 字段 `--appearance` 设为 `dark`。使用独立 bundle ID 以 release 构建诊断包。正常 release 包没有诊断配置。

打开 5,000 条历史并关闭跟随输出。用 ⇧⌘G 启动一次 4 秒测量，重复三次并以 Time Profiler / Hangs 采样该宿主。输入场景激活合成负载，发送一次任务，待编辑器清空后按间隔连续输入 `m`，使用相同编辑器字体和 2× 窗口。核对结束后的完整草稿及最终工具结果。使用 `Scripts/analyze-m3-pixels.py --help` 查看样本 PID 参数。
