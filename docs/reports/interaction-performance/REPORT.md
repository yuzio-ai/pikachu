## 产品行为

- 展示累计输入、输出、缓存读取 / 写入、累计 Token 与美元估算。累计用量与当前上下文占用分开。没有单价、历史费用不完整、空上下文或统计读取失败时明确显示未知 / 不可用，不按零费用处理。统计标明查询时间与过期状态，不表示服务商余额。
- 历史统计遍历全部有效条目，包含其他分支、压缩和独立用量；对话仍仅展示当前分支。部分写入的历史不提供完整用量结论。Pi JSONL 仍是历史真实来源，未增加第二份消息数据库。
- 原生支持选择、确认、单行输入和多行编辑。请求绑定执行实例与原始请求 ID；重复回复、旧实例、过期和断连后的回复均拒绝。确认不设回车默认同意；多行 Return 换行，Command Return 提交。
- 浏览历史时，后台执行会话的请求通过全局入口处理。弹窗标明所属会话，不把回复写进当前查看会话的草稿。取消、停止、退出和异常断连均收回待回复界面。连续弹窗以请求身份重新创建本地编辑状态。
- 扩展通知、状态、组件文字与标题以原生文字降级呈现。扩展提供的编辑文本进入保留草稿，追加恢复时不覆盖现有编辑。终端自定义组件仍不受支持。
- 默认禁用扩展 / 技能自动发现。用户可明确选择信任的本地扩展，下次激活加载。扩展可以执行代码；原生确认不是工具执行审批或沙箱。
- 快捷键：⌘N 新会话、⌘O 打开项目、⌘L 聚焦输入、⌘Return 发送、⌘. 停止、⇧⌘R 返回执行会话、⇧⌘M 模型设置、⇧⌘U 用量、⇧⌘I 处理待回复请求。
- ⌘Q / 退出菜单先取消扩展请求并关闭工作台弹窗，再进入停止并退出确认。取消退出不会重新发送该扩展请求。退出调用由 AppKit RunLoop 调度，避免 Swift Task 或主队列嵌套退出循环阻塞异步清理；确认后的监督清理策略沿用 M1。

## 边界与可靠性

`AgentRuntimeCore` 增加中立用量、交互与回复类型；Pi 细节留在适配层。UI 不读取 Pi JSON，也不直接管理执行子进程。

停止保持 clear_queue → 保留返回草稿 → 取消待回复交互 → abort → 状态确认。请求只有遇到新的人机交互才延长等待；普通未确认 prompt 仍约 5 秒超时。不会自动重发状态修改命令。

扩展交互最多 16 个待处理请求、每实例 4,096 个已见标识，默认本地有效期 300 秒。Pi 1.5.2 没有独立过期通知，因此在其声明期限前保守取消，并在命令完成、停止或断连时退役请求。超限内容取消整条交互，不截断确认内容后要求用户同意。

生产 RPC 读取采用有界块读取、独立响应匹配与可排空事件缓冲；最多 128 个事件 / 8 MiB，允许一个不超过 16 MiB 的完整记录单独占用。领域事件通道最多 128 个信封，只合并相邻文本与工具快照，控制事件保持顺序，反压不丢终态。不同执行实例不能因批处理而被重新标记来源。工具预览保留 65,536 字符，完成后释放适配器中的运行工具快照。

生产管道写入设置 FD 级 `F_SETNOSIGPIPE`，对端关闭 stdin 时返回写入错误，不让宿主因 SIGPIPE 退出；写入和关闭采用同一串行锁。独立子进程验证在 SIGPIPE 默认处理下仍能拒绝写入并正常退出。

M0 的 C 身份检查、PID / 出生时间校验和独立监督算法保留。共享 RPC 文件增加了可选的生产流式模式；**不能再声称全部 M0 源文件字节未变**。原探针默认模式、监督专项和管道测试分别回归，具体指纹见证据清单。监督的同用户、标记 / 谱系和 fail-closed 适用边界沿用 [M0 报告](../pi-rpc-compatibility/SUPERVISION.md)。

恢复时，不把 Pi 的 `unknown` 占位模型保存为有效模型配置。扩展指令可能不创建会话文件；未确认持久化且文件不存在的进程内分配，在重启后回到本地待初始化会话，保留草稿与提交记录。已确认存在的历史若丢失，仍阻止执行。未决提交仍需核对，不因上述清理而自动重发。

## 验证方式

```sh
swift test --disable-sandbox
swift test --disable-sandbox --package-path Tools/M0Validation
.build/release/m3-verify
.build/debug/m2-verify
.build/release/m2-verify --real
.build/release/m1-verify --real
Tools/M0Validation/.build/debug/m0-verify --suite supervision
.build/debug/m1-verify --baseline
python3 Scripts/build-app.py --configuration release --output dist/Release/Pikachu.app
```

M3 集成使用真实 Pi 的扩展命令，不调用模型；大输出由独立合成协议进程生成。M1 `--real` 使用隔离项目和已有认证，会产生模型调用费用。失败尝试独立保存，不改写成全绿结果。

原生诊断使用独立 bundle ID、临时项目、专用 SwiftData 索引和无凭据 Agent 目录。`m3-verify --prepare-native <目录>` 生成 M0 100 / 5,000 条混合历史和 10 MiB 输出样本。构建脚本仅在明确传入 `--fixture-config` 且使用独立 bundle ID 时打包诊断配置；正常构建不含该配置或指标文件。

客户端诊断只记录时间、计数和本地标识，不记录草稿文字、模型密钥或工具正文。原始 Instruments trace 留在临时目录；导出的项目证据只保留本次验证所需内容。

原生测试曾因扩展文件位于仓库 Documents 路径而连接超时：当时 Node 采样观察到文件 open 等待，RPC 收到请求但没有输出。相同夹具复制到专用临时目录后恢复连接。阻塞时的 Node 原始采样被后续成功诊断覆盖，现保留失败 RPC 元数据及路径对比；没有 OS 审计日志证明具体策略原因。未修改系统隐私授权，也未引入 RPC 桥接；生成器现在把原生夹具复制到临时目录。

退出实现的两个失败候选分别阻塞在 Swift Task 和主队列的嵌套 `terminate:` 循环。首个由用户强退，第二个通过活动监视器仅强退已核对 PID 的测试宿主；监督器均完成清理。最终 RunLoop 候选重新验证了等待输入 → ⌘Q → 确认 → 宿主及监督器退出。失败记录独立保留，不记作成功退出。
