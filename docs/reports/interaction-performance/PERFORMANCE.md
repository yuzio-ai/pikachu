# M3 性能测量与门禁

**2026-11-18 最终构建通过 M3 的冻结性能目标。** 同一宿主的长历史滚动 p95 为 17.78 ms，流式输入到字形呈现 p95 为 47.88 ms。启动、历史切换、内存和领域测试也已通过。 [原生窗口呈现复验](NATIVE-PIXELS.md)

以下保留首次实施时的测量和工具限制。冻结阈值沿用 [M1 性能目标](../m1/PERFORMANCE.md)。

## 环境与端点

同机 Mac16,8 / Apple M4 Pro，12 核、24 GiB，macOS 27.2.1（26B131），Xcode 27.2 / Swift 6.4.2。原生包使用 release 优化、独立 bundle ID、无凭据临时 Agent 目录。启动 / 切换候选窗口为 1120 × 780 pt；最终深色负载截图为 2198 × 1860 px（约 1099 × 930 pt），不能将两组当成相同窗口条件。设备连接 3024 × 1964 内屏与 3840 × 2160 外屏，未可靠固定 / 记录刷新率。测试时其他桌面应用仍运行，没有隔离成专用性能实验环境。

历史由 M0 生成器生成 100 / 5,000 条混合样本，调整头部 cwd 至临时项目；长历史投影包含 5,001 个 UI 行。冷进程启动表示每次退出后重新创建进程，OS 文件缓存保持热状态，不代表冷磁盘启动。使用 nearest-rank p95；样本 10 次时 p95 等于最大值。

诊断 `first-editor-client-draw` 从内核进程出生时间计到可见编辑器的 NSView.draw。历史端点从侧栏操作计到加载完成且有内容的客户端绘制。它们不包含 WindowServer 最终呈现，也不证明光标或文字的实际像素已显示。按键事件到编辑器诊断绘制同样只作辅助观察。

| 10 MiB 输出期间输入 p95 ≤ 50 ms、最大 ≤ 100 ms | 领域 yield、客户端绘制及人工 / 自动化可操作性不代替按键到像素。屏幕端点未测，未通过。 |
| 输出后常驻内存增量 ≤ 200 MiB，积压有界 | CLI 与原生均验证 10 MiB 输出和 65,536 字符预览。原生 RSS 峰值 / 保留增量为 56.16 / 39.83 MiB。输入目标未通过，因此整项保留待验收。 |
| debug 5,000 条领域投影 ≤ 100 ms，增量 / 草稿 p95 ≤ 5 ms | 同一协调器夹具回归通过，具体轮次见 [领域数据](evidence/projection.json)。排除 SwiftUI、网络和屏幕呈现。 |

上述启动 / 切换数值来自最终手动高度缓存 UI 候选。其后增加了退出路由、错误清理、失败元数据与管道安全写入。它们不是最终可执行文件的完整性能复验；原始文件、候选差异和端点见 [证据清单](evidence/manifest.json)。

最终深色负载实例接收了流式阶段的 30 个真实按键，全部保留。按键到下一次编辑器客户端绘制 p95 32.15 ms、最大 33.44 ms，仅为辅助端点；没有测量屏幕呈现。RSS 每 100 ms 采样一次，共 250 次，基线取前 5 次中位数，保留量取末 10 次中位数。指标含诊断开销，不等于进程 physical footprint。原始数据见 [客户端端点](evidence/client-summary.json) 和 [RSS 样本](evidence/native-rss.json)。

## Instruments 限制与未通过的尝试

按 toc → track → detail 检查了 Time Profiler / Hangs、Display 和 Core Animation 组合。没有把系统刷新、其他应用的 surface 或自动化调用耗时当成 Pikachu 帧率。

- Core Animation FPS 明确报告 macOS 无该 FPS 指标。
- Frame Lifetimes 组合出现 `set-column expected backtrace, got tagged-backtrace` 内部错误；导出部分记录起点为 0，Event Latency 为 n/a，不可用于延迟验收。
- Display 导出未找到可归属 Pikachu 的有效 surface。整屏刷新不能补充为本应用帧序列。
- Core Animation Server 采样期间，原生自动化返回窗口不可用；宿主仍存活，未完成受控滚动 / 输入序列。空闲时间采样无停顿不代表滚动通过。
- 此前不同 UI 候选在 AX 遍历期间有 296–489 ms 停顿；其中一个 464.79 ms 停顿发生在首次滚动事件之前。这些失败保留为失败，不能绑定到当前候选，也不能从报告中删除。

后续需要在同一最终 release 指纹上完成可归属应用的帧与屏幕呈现测量，复核 AX 查询下的主线程停顿，并重复流式输入、5000 条滚动和大输出场景。若工具仍不可用，应更换可建立相同端点的测量方法；阈值与验收含义保持不变。
