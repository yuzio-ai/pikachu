# 极简桌面界面审查

让当前任务最醒目，让状态和下一步容易找到，让需要细读的信息保有足够密度。以 T3 Code 参考图中的层级、对齐、分组和前景聚焦为灵感。沿用 Zivvi 的 [设计令牌](../../../DESIGN_TOKEN.md)、[DesignSystem](../../../Zivvi/DesignSystem/)及适用的页面设计。按项目组件决定颜色、圆角、字号、材质和交互。保留 Zivvi 自己的品牌与布局。

## 平铺布局

平铺布局是 Zivvi 现代极简风格的基础。工作台、对话、设置、检查器、列表和浮层的内容都按这一原则组织。

- **同层内容共用底色**。每个界面层按组件令牌选用底色。工作台、设置和功能浮层沿用 `ZivviTheme.pageBackground`，纯选项菜单和悬停预览沿用各自的面板底色。同层的连续内容直接铺在该层底色上。普通分组省去额外的卡片底色、圆角、描边和阴影。 [锚定浮层令牌](../../../DESIGN_TOKEN.md#锚定浮层)
- **用排版建立层级**。用标题、对齐、稳定的行间节奏和组间留白表达归属。需要划清区域或分组时，使用 `ZivviTheme.subtleDivider` 或设计系统已有的面板分隔线。
- **让功能边界清楚**。输入框、按钮、消息和状态反馈沿用各自的组件样式。菜单、预览和模态面板可保留表达前景层级的轮廓和表面，内部的普通分组继续平铺。
- **复用选中与焦点样式**。同类导航项复用设计系统的选中态，键盘焦点单独显示。智能体设置的栏目和标签沿用工作台会话卡片的 `ZivviTheme.selected`，「新会话默认」标记独立表达业务状态。

参考 [工作台与应用面板统一底色](../../../docs/design/workbench-unified-background.md)和 [智能体设置定稿](../../../docs/design/provider-settings.md#视觉规范)。

## 审查顺序

1. 定位本次改动的界面、主要任务和关键状态。对照现有实现或已批准的设计，明确本次应保留的功能、信息和入口。
2. 先看整体布局。用户能否识别当前位置、当前对象和下一步？常用操作应容易找到，次要细节可以按需展开。对照平铺原则，检查多余的分组容器和仍需保留的功能边界。
3. 再看局部。组间留白应明显大于组内留白。同类控件、图标和文字按统一基线对齐。用字号、字重和对比建立层级，保持正文、关键状态和控件标签清晰。强调色传递状态或数据分类，选中、危险和错误也用文字、图标或形状表达。阴影表达浮层深度，模糊和遮罩把注意力移向当前前景。
4. 按改动挑选下列场景和状态核对。优先指出影响阅读、操作或恢复的问题，再写纯视觉取舍。每项发现给出位置、证据、影响和最小修正。使用源码核对规则、组件和状态覆盖，用截图判断可见结果。需要运行证据的结论标为待验证，并遵循 [项目原生验收授权](../../../AGENTS.md#构建与验证)。

对比截图前，先对齐窗口尺寸、系统外观、应用字号、界面语言和页面状态。页面状态包括当前选中项、展开状态和滚动位置。标明有意改变的条件。其他条件无法对齐时，说明差异会影响哪些判断。

## 按界面核对

| 界面 | 检查重点 |
| --- | --- |
| 工作台与对话 | 导航、阅读和工具各有稳定位置。宽屏限制正文行宽，正文、表格和输入区建立清楚的对齐关系。窄窗优先保留当前任务和输入区，次要面板使用已有的折叠或重排方式。代码、长路径和宽表格在各自区域处理溢出。可调宽度的分隔线要核对拖拽命中区、水平调整光标以及悬停和拖拽时的高亮。高亮与常态占用相同的布局空间。核对拖拽是否在允许范围内调整宽度，以及 VoiceOver 能否读出并通过现有辅助功能操作调整宽度。 [面板边界令牌](../../../DESIGN_TOKEN.md#鼠标悬停) |
| 命令面板与弹层 | 搜索、当前选择、辅助信息与快捷键各有固定位置。菜单跟随触发位置，模态面板保持明确的关闭路径。核对初始焦点、键盘导航、Esc 的关闭范围和关闭后焦点恢复。 |
| 设置与检查器 | 按用户要完成的操作分组。同类标签、说明和控件对齐，高级选项按需折叠。开启、关闭、禁用和影响范围应易辨认。窄窗中可将复杂控件重排到说明下方，保留操作和反馈的位置关系。 |
| 列表、文件树与用量面板 | 用统一行高或稳定的行内节奏支持扫读，关键数字同列对齐。数据按总量、趋势、明细组织，保留单位、时间范围和筛选状态。系列和正负变化用图例、标签或符号辅助识别。 |

## 容易遗漏的状态

- **操作与恢复**。检查相关的空态、无搜索结果、加载、执行中、成功、错误和禁用状态。需要等待时给出明确反馈。失败后把原因和可用的恢复操作放在发生问题的位置。精简文案时保留必要的权限范围、风险和结果。
- **输入与焦点**。悬停、键盘焦点、选中、按下和禁用应可区分。常用操作应有可见入口，悬停出现的操作也应能通过键盘或菜单访问。图标按钮要有可访问名称。可见图标大小与点击区域分别核对。
- **无障碍分组与顺序**。平铺后核对无障碍树中的标题语义，以及标签、说明、错误反馈与对应控件的关联。检查 VoiceOver 的阅读顺序及选中、开关和展开状态的播报。窄窗重排后，键盘遍历顺序应与可见的操作顺序一致。
- **外观与可读性**。检查相关的浅色、深色、提高对比度和减少透明度设置。核对平铺分组能否通过留白和分隔线辨认，辅助文字、选中态和焦点是否清楚。减少透明度时，用可读的表面和边界保住层级。用最小支持窗口、较大字号和长本地化文案检查关键操作是否仍可见。
- **减少动态效果**。开启系统的「减少动态效果」后，核对非必要动画是否减弱或停用。加载、执行中和操作结果仍应通过文字、静态状态标记或可读的进度反馈辨认。
