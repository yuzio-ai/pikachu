# 极简桌面界面审查

让当前任务最醒目，让状态和下一步容易找到，让需要细读的信息保有足够密度。以 T3 Code 参考图中的层级、对齐、分组和前景聚焦为灵感。沿用 Pikachu 的 [设计令牌](../../../DESIGN_TOKEN.md)、[DesignSystem](../../../Pikachu/DesignSystem/)及适用的页面设计。按项目组件决定颜色、圆角、字号、材质和交互。保留 Pikachu 自己的品牌与布局。

## 审查顺序

1. 定位本次改动的界面、主要任务和关键状态。对照现有实现或已批准的设计，明确本次应保留的功能、信息和入口。
2. 先看整体布局。用户能否识别当前位置、当前对象和下一步？常用操作应容易找到，次要细节可以按需展开。增加容器前，先看对齐、间距、底色或分隔线是否已能表达关系。
3. 再看局部。组间留白应明显大于组内留白。同类控件、图标和文字按统一基线对齐。用字号、字重和对比建立层级，保持正文、关键状态和控件标签清晰。强调色传递状态或数据分类，选中、危险和错误也用文字、图标或形状表达。阴影表达浮层深度，模糊和遮罩把注意力移向当前前景。
4. 按改动挑选下列场景和状态核对。优先指出影响阅读、操作或恢复的问题，再写纯视觉取舍。每项发现给出位置、证据、影响和最小修正。使用源码核对规则、组件和状态覆盖，用截图判断可见结果。需要运行证据的结论标为待验证，并遵循 [项目原生验收授权](../../../AGENTS.md#构建与验证)。

## 按界面核对

| 界面 | 检查重点 |
| --- | --- |
| 工作台与对话 | 导航、阅读和工具各有稳定位置。宽屏限制正文行宽，正文、表格和输入区建立清楚的对齐关系。窄窗优先保留当前任务和输入区，次要面板使用已有的折叠或重排方式。代码、长路径和宽表格在各自区域处理溢出。 |
| 命令面板与弹层 | 搜索、当前选择、辅助信息与快捷键各有固定位置。菜单跟随触发位置，模态面板保持明确的关闭路径。核对初始焦点、键盘导航、Esc 的关闭范围和关闭后焦点恢复。 |
| 设置与检查器 | 按用户要完成的操作分组。同类标签、说明和控件对齐。开启、关闭、禁用和影响范围应易辨认。长说明可换行，控件保留操作空间。 |
| 列表、文件树与用量面板 | 用统一行高或稳定的行内节奏支持扫读，关键数字同列对齐。数据按总量、趋势、明细组织，保留单位、时间范围和筛选状态。系列和正负变化用图例、标签或符号辅助识别。 |

## 容易遗漏的状态

- **操作与恢复**。检查相关的空态、无搜索结果、加载、执行中、成功、错误和禁用状态。需要等待时给出明确反馈。失败后把原因和可用的恢复操作放在发生问题的位置。精简文案时保留必要的权限范围、风险和结果。
- **输入与焦点**。悬停、键盘焦点、选中、按下和禁用应可区分。常用操作应有可见入口，悬停出现的操作也应能通过键盘或菜单访问。图标按钮要有可访问名称，开关和折叠控件应提供状态。可见图标大小与点击区域分别核对。
- **外观与可读性**。检查相关的浅色、深色、提高对比度、减少透明度和减少动态效果设置。辅助文字、分隔线和焦点指示需要足够清楚。系统减少视觉效果时，用可读的表面和边界保住层级。用最小支持窗口、较大字号和长本地化文案检查关键操作是否仍可见。
